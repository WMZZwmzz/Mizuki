# 17 | Z-Image Turbo:2 秒一张图,本地生图的速度天花板

> 发布时间:2025-11-27(Turbo);2026-04 生态成型
> 文体:极客评测/跑分报告(数据密集、技术狂热、直给)
> 一句话:4090 上 2-5 秒出一张 1024² 图——6B 参数、8 步推理,这就是 2026 年本地生图的速度天花板。

## 先看跑分

| 指标 | 数值 |
|---|---|
| 参数 | 6B |
| 推理步数 | 8-9 步(NFE≈8) |
| 出图时间(4090) | 2-5 秒 |
| 出图时间(H800) | 亚秒级 |
| 最低显存 | 6GB(GGUF) |
| 许可 | Apache 2.0(可商用) |

## 它为什么这么快:四个数字拆穿

1. **蒸馏压缩步数**:约 8 次模型评估出图,对比 SDXL/FLUX dev 的 20-30 步,单图算力降约 3 倍。
2. **紧凑骨干**:6B 参数,约为 FLUX.1(12B)的一半。
3. **CFG 关闭**:Turbo 以 CFG≈1 运行,每步单次前向——普通模型 CFG>1 要双倍前向。
4. **S3-DiT 架构**:Scalable Single-Stream Diffusion Transformer——文本、视觉语义、图像 VAE token 拼成单一序列,比 FLUX 的并行双流更简更快。

**综合效果**:消费卡秒级出图,质量对标 20B 级闭源模型(尤其写实人像)。

## 家族三兄弟

| 变体 | 步数 | 用途 |

| Turbo | 8-9 | 主力日常,最快,无负向提示词 |
| Base | 20-30 | LoRA 训练/高质量,支持负向提示词 |
| Edit | 20-30 | 自然语言指令编辑 |

## 显存与量化

| FP8 | ~8GB | 中端 |

## 部署三件套(别踩坑)

1. 扩散模型 + 文本编码器(`qwen_3_4b.safetensors` 放 `text_encoders/`)+ VAE——缺一不可。
2. **CFG 必须 1.5-2.0**:蒸馏模型对参数挑剔,SD 的 6-9 会让它过饱和。
3. **LoRA 架构绑定**:只能用 Z-Image 架构 LoRA,SDXL LoRA 不兼容。

## 对比实测:它 vs FLUX

- 短文字渲染:打平。
- **长文字渲染:Z-Image 胜**(FLUX 会出错)。
- 代价:Z-Image 文字偏"过整齐",略欠自然融入。

## 实测场景

- **线稿上色**:Z-Image + ControlNet Canny,1024² 约 6.3 秒(RTX 4060),对比 SDXL+ControlNet 11.7 秒——快近一半。
- **批量草稿**:秒级出 100+ 候选,交互式体验。

## FAQ

**Q1:为什么这么快?** 蒸馏(8 步)+ 6B 骨干 + CFG 关闭 + S3-DiT。
**Q2:Turbo 还是 Base?** 日常用 Turbo;负向提示词/精细控制/LoRA 训练用 Base。
**Q3:过饱和怎么办?** CFG 降回 1.5-2.0(Turbo 的命门)。
**Q4:SDXL LoRA 能用吗?** 不能,架构不兼容;用 Z-Image LoRA。
**Q5:最低显存?** 6GB(GGUF Q3/Q4)。
**Q6:文字渲染?** 中英双语精准,长文字优于同体积 FLUX。
**Q7:能商用吗?** Apache 2.0,可商用。
**Q8:ControlNet 配合?** Canny 等好用,Strength 约 0.85。

## 实战配方

**A:实时交互生图** — 4090 部署 Turbo → 边聊边改秒出图 → 灵感风暴/客户演示。
**B:批量草稿流水线** — Turbo 秒级 100+ 候选 → 筛选 → Base 精修。
**C:线稿上色** — ControlNet Canny(0.85)→ Turbo 16 步 → 分镜/漫画批量。
**D:LoRA 定制** — Base 训练 → Turbo 推理(0.6-1.0;堆叠≤3 个 0.3-0.5)。

## 风险清单

- 参数敏感:CFG/步数挑剔,新手易踩坑。
- 生态早期:LoRA/ControlNet 少。
- 无负向提示词:Turbo 无法用负面约束。
- 长文字"过整齐":氛围场景需权衡。
- 架构封闭:LoRA 无法跨架构复用。
